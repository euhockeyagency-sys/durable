# European Hockey Agency — анализ проекта и что уже сделано

Снимок на 14 октября 2026. Основан на коде, git-истории (2433 коммита, 18.07.2026 — 10.10.2026), документах в `docs/` и заметках проекта. Всё, что не проверялось напрямую, помечено «не проверено».

## 1. Что это за проект

Сайт хоккейного агентства **European Hockey Agency (EHA)**: агент Вячеслав Морщенок (Viachaslau Marshchonak), работает с 2016 года, офис в Гданьске. Утверждённые данные бренда (контакты, цифры «100+ игроков», «10+ рынков», «48 ч») — в [BRAND.md](BRAND.md).

Сайт делает три вещи:

1. **Привлекает трафик** справочным контентом на RU и EN: гайды по странам, справочник лиг, юниорские маршруты, документы и визы, зарплаты.
2. **Квалифицирует игрока**: калькулятор уровня, затем форма заявки.
3. **Принимает заявки** игроков и клубов, сохраняет их в Supabase, уведомляет агента и даёт кабинет `/admin` для работы с лидами.

## 2. Архитектура

| Слой | Что используется |
| --- | --- |
| Runtime | Node.js 22, Express 5, CommonJS |
| Frontend | Статический HTML/CSS/JS без сборщика, локальные шрифты |
| Хранилище | Supabase (проект `lvcrutflxscynaewkcno`, eu-west-3), приватный bucket `application-files`, RLS |
| Уведомления | Telegram + Resend (email) |
| Защита форм | Cloudflare Turnstile, honeypot, rate limit |
| Аналитика | GA4 + Яндекс Метрика |
| Хостинг | VPS UpCloud: Caddy → Node, systemd-юнит `eha`, каталог `/opt/eha` (`railway.json` в репозитории не отражает реальный деплой) |
| Деплой | push в `main` → GitHub Actions (тесты + SSH-деплой) |
| MCP | Отдельный пакет `mcp/` (ESM): читает и правит страницы прямо на сервере |

Ключевые файлы:

- [src/app.js](src/app.js) (1107 строк): маршруты, отдача и преобразование HTML, SEO, sitemap, RSS, форма клубов, `/admin`.
- [src/locales.js](src/locales.js): таблица `PAGES` — соответствие RU/EN URL. Питает переключатель языка, hreflang, 301-редиректы.
- [src/applications.js](src/applications.js), [src/validation.js](src/validation.js), [src/messages.js](src/messages.js): приём и валидация заявок.
- [src/config.js](src/config.js): конфигурация из окружения. Каждая интеграция включается сама, когда заданы её ключи.
- [src/admin-auth.js](src/admin-auth.js): вход в кабинет по паролю, подписанная cookie.
- [src/league-facts.js](src/league-facts.js), [src/league-editorial.js](src/league-editorial.js), [src/guide-index.js](src/guide-index.js), [src/league-list.js](src/league-list.js): контент и индексы.
- [public/assets/leagues.src.js](public/assets/leagues.src.js): единый источник справочника лиг. Из него `node scripts/build-leagues.js` генерирует `leagues.ru.js`, `leagues.en.js` и строки таблиц.

Модель доменов: английский сайт в корне `eurohockeyagency.com`, русский под `/ru/`. Старый домен `eurohockeyagency.ru` служит только источником 301-редиректов.

## 4. Что сделано

### Инфраструктура и деплой
- Перенос на одну доменную модель (EN в корне, RU в `/ru/`), 301-редиректы со старого `.ru` домена.
- Деплой через GitHub Actions: тесты, затем SSH на сервер. Ключ ограничен запуском `deploy.sh`.
- Исправлены расхождения серверной копии с `origin/main` (сентябрь–октябрь). Корневая причина: MCP коммитит до тест-гейта, и коммит застревал на сервере. Добавлен `scripts/sync-checkout.sh` (ребейз серверных коммитов, дубликаты отбрасываются, при конфликте создаётся backup-ветка). Он вызывается из `scripts/deploy-production.sh`.
- Тест-гейт MCP исправлен: он смотрит на `require("supertest")` в самом тест-файле, а не на имя файла.

### Приём заявок
- Форма игрока: серверная валидация, согласия, данные представителя несовершеннолетнего, до 3 файлов, лимит 10 MiB, проверка MIME, расширения и сигнатуры.
- Форма клубов (`/api/club-request`): сохранение в Supabase, затем уведомление.
- Заявка считается принятой после сохранения: сбой уведомления не превращается в ошибку для пользователя.
- Ссылка Elite Prospects сделана необязательной (миграция `20261007231242`, 08.10).
- Страница-источник передаётся в форму (`Carry page intent into the application form`).
- Исправлено несовпадение параметра лиги в CTA на страницах лиг.

### База данных (6 миграций)
1. `create_applications`: таблицы `applications`, `application_files`, `application_notifications`, RLS, приватный bucket.
2. `schedule_application_cleanup`: ежедневная очистка через `pg_cron`. Удаляются заявки старше 12 месяцев со статусами `new`, `rejected`, `archived`.
3. `relax_contract_status`.
4. `create_club_requests`: `club_requests` и `club_request_notifications`.
5. `application_followups`: поля `internal_note` и `next_contact_at`. Заявка с датой следующего контакта не удаляется очисткой.
6. `relax_elite_prospects_url`.

Живая проверка Supabase (31.07.2026): миграции применены, anon-ключ получает `42501` на SELECT и INSERT, bucket не листится.

## 5. Текущее состояние проверок

Запущено 14.10.2026 на macOS:

- `npm run check`: проходит.
- `npm test`: **145 из 149 проходят, 4 падают**. Все четыре в `test/sync-checkout.test.js`. Причина в сообщении теста: `scripts/sync-checkout.sh: line 17: timeout: command not found`. Команда `timeout` есть в GNU coreutils (Linux), но не в macOS. Это проблема окружения, а не регрессия кода. Что тесты проходят на Linux в CI, я **не проверял**.
- `git status`: чисто на момент начала сессии.

## 6. Известные проблемы и риски

1. **Скрипт `sync-checkout.sh` зависит от `timeout`.** Локально на macOS его тесты не проходят. Варианты: `gtimeout` / fallback в скрипте или пропуск тестов без `timeout`.
2. **Письма уходят с общего адреса `onboarding@resend.dev`.** Домен `eurohockeyagency.com` в Resend не подтверждён, SPF/DKIM/DMARC в DNS нет. Письма могут попасть в спам. Записи в hoster.by может добавить только владелец.
3. **MCP пишет в `main` в обход проверок.** Он не регистрирует новые страницы в `PAGES` и не нормализует ссылки, поэтому новая страница может сделать CI красным. 1854 из 2433 коммитов (76 %) — это «MCP edit/write». Правки MCP коммитятся до тест-гейта, поэтому нужно проверять расхождение серверной копии и `origin/main` до работы через MCP.
4. **Миграции Supabase и SSH-деплой идут независимо.** Шаг миграций в `deploy.yml` пропускается (в секретах GitHub только `DEPLOY_SSH_KEY`), миграции выкладывает интеграция Supabase↔GitHub. Порядок не гарантирован, поэтому после пуша со схемой нужно проверять `list_migrations`.
5. **Лиги: данные и страницы могут расходиться.** Справочник — 58 записей, страниц лиг 49. Ранняя заметка про расхождение хаба и источника (40 строк против 36 лиг) устарела, актуальное соотношение не сверялось.
6. **`README.md` частично устарел**: пишет «Node.js 20+», а проект требует Node 22.
7. **Бонусные языки (sv/fi/cs/de)**: по одной странице, вне модели `PAGES`. Языковой переключатель продублирован в HTML вручную, общего шаблона нет. Полноценный N-язычный сайт потребует рефакторинга бинарной модели `ru/en`.
8. **Данные о доставке аналитики не подтверждены**: браузерный код проверен, отчёты GA4/Метрики — нет.
9. **Хоккейные факты меняются** (лимиты легионеров, окна, возрастные категории). Даты проверки указаны в `docs/*-factcheck.md`, но перед сезоном их нужно обновлять.

## 8. Как работать с проектом

```bash
npm ci           # зависимости
npm run dev      # локальный запуск (нужен .env)
npm run check    # синтаксис
npm test         # тесты
node scripts/build-leagues.js   # после правки leagues.src.js
```

Правила репозитория — в [AGENTS.md](AGENTS.md). Главное:

- В исходных HTML используйте логические пути без `/ru/`.
- Новую двуязычную страницу добавляйте в обе папки и в `PAGES`.
- Не правьте вручную `leagues.ru.js` / `leagues.en.js`.
- Секреты и данные заявок не попадают в `public/` и Git.
- Push в `main` запускает деплой на production.
