# Автоматизация входящих заявок игроков

Состояние на 18.11.2026. Всё работает на существующем стеке: Express, Supabase (таблица `applications`, приватный bucket `application-files`), Telegram и email (Resend), админка `/admin`. Параллельной CRM нет.

## Как обрабатывается новая заявка

1. Игрок заполняет форму `/contact` (EN) или `/ru/contact`. Если есть ссылка на Elite Prospects, кнопка «Заполнить из Elite Prospects» запрашивает `POST /api/ep-lookup`.
   - Если ключ EP API настроен, поля заполняются данными API. Игрок проверяет их, исправляет и ставит отметку «Я проверил заполненные данные».
   - Если ключа нет или EP недоступен, форма объясняет это и продолжает работать вручную. Введённые данные не теряются.
2. `POST /api/applications` проверяет поля на сервере: старые правила, новые поля (`src/intake/profile.js`), фото, лимит 3 файла и 10 MiB, согласия, данные представителя несовершеннолетнего, honeypot, лимит запросов.
3. Повтор. Та же заявка в течение 24 часов возвращает прежний номер, новая запись не создаётся. Изменённая повторная подача сохраняется новой заявкой со ссылкой на предыдущую (`previous_application_id`).
4. Заявка сохраняется в Supabase. Тут же сохраняются:
   - профиль, подтверждённый игроком (`profile`, `birth_date`);
   - внутренняя предварительная оценка (`assessment`);
   - отдельные согласия на публичное использование фото и кейса;
   - хеш токена владельца;
   - фото, если загружено.
   При ошибке уже записанные файлы удаляются, как и раньше.
5. Агенту уходит уведомление через очередь (`src/intake/notification-queue.js`). Ошибка мессенджера не превращается в ошибку для игрока. Повторные попытки идут с паузами 1, 5, 30 и 120 минут, затем статус `abandoned`. Сервер проверяет очередь каждые 2 минуты. Повторить вручную можно кнопкой в карточке заявки.
6. Игрок видит на странице успеха конкретные рекомендации на языке формы: что добавить (видео, статистику, уровень, цели…), как обновить заявку, как запросить ручное рассмотрение, и может скачать свою PDF-карточку. Внутренняя категория игроку не показывается и автоматически никуда ему не отправляется.
7. Агент открывает заявку в `/admin/applications/<id>`. Там:
   - данные игрока;
   - оценка с объяснением и списком недостающего;
   - ручная корректировка категории (причина обязательна, история сохраняется);
   - поле «Заключение агента» для PDF;
   - создание, повторное создание, просмотр и скачивание PDF;
   - ссылка для внешней передачи на 14 дней;
   - статусы доставки уведомлений.

## Где меняются правила оценки

`src/intake/assessment-rules.js` — единственное место. После правки увеличьте `version`: каждая сохранённая оценка хранит версию правил и дату расчёта.

- Категории: Tier A, Tier B, Tier C, «Не наш профиль», «Нужна ручная проверка». Это приоритет очереди агента, а не оценка таланта.
- Режим `preliminary`. Автоматического отказа нет: заявка всегда сохраняется, агент видит результат и может его изменить.
- Спортивный сигнал повторяет опубликованную логику калькулятора уровня EHA: базовый балл по уровню лиги, нормы очков за игру отдельно для нападающих и защитников (у вратарей нормы нет), поправка на возраст. Уровни лиг берутся из `public/assets/leagues.src.js`.
- Пороги Tier не утверждены EHA (`approved: false`), сейчас они совпадают с полосами калькулятора. Их нужно утвердить.
- Остальные части оценки считаются отдельно:
  - полнота профиля (веса полей);
  - направления EHA (возрастные диапазоны);
  - что проверить по документам (несовершеннолетний, несколько гражданств, рынок).
- Отсутствие статистики не даёт нулевую оценку, а только снижает полноту. Гражданство никогда не исключает профиль.

## Интеграции: что реально работает

| Интеграция | Состояние |
| --- | --- |
| Supabase (заявки, файлы, PDF) | работает; нужна миграция `20261118120000_intake_automation.sql` |
| Telegram, email | работают, как и раньше; текст уведомления заменён карточкой агента |
| Elite Prospects | адаптер официального API готов, но **не подключён**: нужен платный ключ организации (`EP_API_KEY`, запрос на api@eliteprospects.com). Сопоставление полей ответа проверено только на тестовых данных и сверено с документацией, не с живым ключом. Сайт EP не скрейпится; используется только числовой ID из ссылки, запросы идут на фиксированный хост API; есть тайм-аут, запрет перенаправлений и лимит частоты. Фото из EP не используется |
| WhatsApp | адаптер официального WhatsApp Business Cloud API готов, выключен; нужны `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_TO` и одобренный шаблон `WHATSAPP_TEMPLATE` с 3 параметрами. Личная сессия WhatsApp не автоматизируется |
| Песочница уведомлений | `NOTIFY_MODE=sandbox`: доставка записывается как `sandboxed`, никому ничего не отправляется |

Пример карточки и PDF на вымышленных данных: `node scripts/preview-intake.js /tmp/sample.pdf`.

## Доступ к данным

- Внутренняя оценка, причины и заметки есть только в админке и в уведомлении агенту. Их нет в ответах публичного API, на странице успеха и в PDF.
- PDF хранится приватно в `application-files/<id>/player-card.pdf` и зарегистрирован в `application_files`, поэтому функция очистки удалит его вместе с заявкой (12 месяцев для неактивных).
- Доступ к PDF:
  - владельцу заявки: по токену, который возвращается один раз в браузер после отправки; в базе хранится только хеш;
  - агенту: в админке;
  - внешнему получателю: по ссылке `/shared/player-card/<token>` на 14 дней, тоже хранится только хеш.
  Публичного каталога игроков нет.
- В PDF нет телефона, email, документов, заметок и Tier. Гражданство подписано «со слов игрока». Самоописание игрока и заключение агента разделены.
- Персональные данные не уходят в аналитику. В логи пишутся только номер заявки и тип ошибки.
